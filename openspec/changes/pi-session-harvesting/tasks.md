## 3. Harvester

- [x] 3.1 Create `internal/harvest/pi.go`: `PiHarvester` struct + constructor, modeled on `ClaudeCodeHarvester` (`internal/harvest/claudecode.go`) — same `HarvestAll(ctx, enqueuer) (harvested, skipped, errCount int)` signature, same presence-based skip flow (a document's mere existence at the session's `source_path` skips re-summarization — NOT a content-hash comparison against a freshly-rendered version; see spec.md's corrected dedup requirement), same `SessionSummarizer`/`ChunkEnqueuer` integration. `HarvestAll` MUST emit its own structured log line with `Str("source", "pi")`, mirroring `ClaudeCodeHarvester.HarvestAll`'s existing per-source log line (`claudecode.go:104-110`) — required so task 6.3 can verify Pi-specific counts on a box running multiple harvesters (found in review, MEDIUM).
- [x] 3.2 Implement the session-file parser per design.md's corrected schema: read the first line as the `type:"session"` header (`id`, `cwd`, `timestamp`); for subsequent lines, skip `model_change`/`thinking_level_change`; for `type:"message"` lines, dispatch on the *nested* `message.role` (`user`, `assistant`, **and `toolResult` — a distinct top-level role, not a sub-part of `assistant`**) and render each `message.content[]` block by its `type`: `text` → its text; `toolCall` → a compact tool-invocation line; `thinking` → a labeled thinking section; `image` → a placeholder line. On a malformed line (including a truncated/partial final line), **skip only that line and continue parsing the rest of the same session file** — matching `ClaudeCodeHarvester.parseJSONLFile`'s actual per-line-skip behavior (`claudecode.go:407-419`) exactly. Do **not** discard the whole session on one bad line (found in review, MEDIUM — the original draft specified whole-session-skip, which diverges from the Claude Code precedent this harvester claims to model itself on).
- [x] 3.3 Add `internal/harvest/pi_test.go`: unit tests with fixture JSONL content (no real filesystem I/O beyond `t.TempDir()`) covering: well-formed session render across all three roles (`user`/`assistant`/`toolResult`) and all four content-block types (`text`/`toolCall`/`thinking`/`image`), single-malformed-line skip-and-continue (session still renders its other valid lines), truncated/partial final line, and the exact `summary://pi/<id>` source path. Unchanged-session presence-skip is covered by `internal/harvest/pi_dedup_integration_test.go` (`//go:build integration`, mirroring `claudecode_dedup_integration_test.go`) against the real `nanobrain_test` Postgres. **Correction (found in the code-review pass):** there is no "changed-session re-ingest" test, because that behavior does not exist — dedup is presence-based, inherited unchanged from `ClaudeCodeHarvester` (see spec.md's corrected requirement); a session file that grows after its first harvest is not re-ingested by either harvester today. A malformed-*header* line (no session ID to key a partial harvest on) is covered by `TestPiHarvestAll_MalformedHeaderCountsAsError`, asserting it counts as an error rather than being silently dropped.
